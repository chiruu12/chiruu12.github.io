OSS-Skills [SHIPPED]

15 executable skills that walk you through your first open source contribution

[github]

// what it does

Most advice about contributing to open source stops at "find a good first issue". The hard parts come after that: working out whether the repo is worth your time, whether someone already claimed the issue, how to get the test suite running, what the maintainer will actually reject you for, and what to do when CI goes red on a fork.

These are 15 skills, one per step, that your coding agent loads and follows. They run in Claude Code, Cursor, Codex, Copilot, Windsurf, Zed, and anything else that reads AGENTS.md. 62 stars so far.

// the pipeline

  • Before you commit time: oss-evaluate-repo checks whether the project is alive and whether outsiders actually get merged. oss-explore-repo and oss-learn-stack teach you the codebase and any unfamiliar tech from the repo itself.
  • Finding work: oss-find-issue for the tracker, oss-find-real-issues for problems nobody has filed yet. Both check the claim before you start, because taking someone else's issue is the fastest way to burn a repo.
  • Doing it: oss-prep-to-contribute, oss-setup-dev-env, oss-contribute, oss-submit-pr. Test-only and docs-only contributions get their own skills.
  • After the PR opens: oss-post-pr for review comments, oss-debug-ci for red pipelines you did not write. This half is the part everyone skips.
  • Becoming a regular: oss-review-prs to build trust in a repo, oss-second-contribution to stop being a drive-by.

// the split

The design rule is that the agent researches and the human thinks. The skills read contribution guides, dig through issue history for prior art, check assignees and linked PRs, and pull CI logs. They do not write your PR description or decide which issue matters. That part is yours, and it is the part maintainers can tell you skipped.

// why I built this

I mentor GSoC contributors at Jenkins. Every year the same questions arrive in the same order, and most of them are not about code. They are about etiquette, process, and knowing when a repo is a dead end. I wrote the answers down as skills so an agent can walk someone through it at 2am instead of me.

Then I used them on my own contributions and found the gaps, which is why the CI and post-PR skills exist at all.

// stack

Markdown skills with YAML frontmatter, an AGENTS.md entry point, and a setup script that installs into whichever agent directory you use. No runtime, no dependencies.
